# Roadmap to Production

Документ описывает, что нужно доработать для перевода Gantt Plan Editor в production-режим.

---

## 🔴 Критические (must-have до прода)

| # | Проблема | Решение | Риск |
|---|----------|---------|------|
| 1 | **Аутентификация и авторизация** — любой может менять план | Добавить OAuth2/JWT (FastAPI middleware), ролевую модель (читатель/редактор/владелец) | Нарушение целостности данных, конкурентные правки |
| 2 | **Персистентность данных** — план хранится только в памяти React-состояния | Добавить БД (PostgreSQL + SQLAlchemy) для хранения проектов и задач, миграции Alembic | Потеря данных при перезагрузке страницы или падении сервера |
| 3 | **Валидация и санитизация ввода** — нет защиты от XSS/инъекций | Добавить валидацию всех входных данных через Pydantic strict mode, экранирование HTML | XSS-атаки через названия задач/сообщения чата |
| 4 | **CORS в продакшене** — сейчас `allow_origins=["*"]` | Ограничить список разрешённых origin конкретным доменом | CSRF-атаки |
| 5 | **Логирование и мониторинг** — только `print` в stderr | Добавить structlog/Python logging, экспорт в OpenTelemetry/Grafana, алерты при отказах LLM | Невозможность отладки и реагирования на инциденты |

---

## 🟡 Важные (should-have)

| # | Проблема | Решение | Риск |
|---|----------|---------|------|
| 6 | **Rate limiting LLM** — нет ограничений на вызовы API | Redis + token bucket, квота на пользователя/проект | Перерасход бюджета LLM API |
| 7 | **Кэширование LLM-ответов** — одинаковые запросы шлются повторно | Кэш промптов и планов в Redis на 5 мин | Лишние расходы, задержка |
| 8 | **Обработка ошибок LLM** — нет retry с backoff | Tenacity/httpx-retry с exponential backoff, circuit breaker | 5xx при временных сбоях API |
| 9 | **Тесты** — нет ни unit, ни интеграционных | pytest для бэкенда (MCP tools, NLP), React Testing Library для фронтенда | Регрессии при доработках |
| 10 | **Сборка фронтенда** — сейчас один HTML через Babel CDN | Vite/CRA-сборка, tree-shaking, минификация | Медленная загрузка, нет code splitting |
| 11 | **Загрузка Excel с зависимостями** — импорт не парсит колонку предшественников | Доработать парсер: распознавать названия задач в столбце E и создавать deps | Неполный импорт данных |

## 🟢 Желательные (nice-to-have)

| # | Проблема | Решение |
|---|----------|---------|
| 12 | **Реальное время** — изменения не синхронизируются между вкладками | WebSocket (FastAPI WebSocket) — бродкаст изменений всем клиентам |
| 13 | **История изменений** — нет undo/redo | Хранить снапшоты состояния, Ctrl+Z |
| 14 | **Мультипроектность** — только один проект | Дашборд проектов, переключение, сравнение |
| 15 | **Экспорт в PDF/изображение** — только Excel | html2canvas / headless Chrome для рендера диаграммы |
| 16 | **i18n** — только русский | react-intl / gettext, перевод на en |
| 17 | **Календарь с выходными** — все дни считаются рабочими | Настройка рабочего календаря (пн-пт, праздники) |
| 18 | **iOS PWA** — нет офлайн-режима | Service Worker, IndexedDB, manifest.json |

## 📋 Порядок закрытия

1. **Неделя 1:** Аутентификация (#1), персистентность (#2), тесты (#9)
2. **Неделя 2:** Валидация (#3), CORS (#4), логирование (#5), сборка фронтенда (#10)
3. **Неделя 3:** Rate limiting (#6), ошибки LLM (#8), импорт зависимостей (#11)
4. **Неделя 4+:** Кэш (#7), вебсокеты (#12), история (#13), мультипроектность (#14)

---

## ⚠️ Риски

- **Зависимость от сторонних LLM API** — сбои OpenAI/Anthropic напрямую влияют на работоспособность. Локальный NLP смягчает, но хуже качество.
- **Сложность NLP для русского языка** — локальный regex-движок хрупок, легко сломать нестандартной формулировкой.
- **Масштабирование** — при >1000 задач auto-расчёт может замедляться, нужна инкрементальная ревалидация.
