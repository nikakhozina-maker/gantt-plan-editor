# Roadmap to Production

## Что нужно доработать для боевого состояния

### 1. Фронтенд

#### Технические долги (сознательно оставлены)

| # | Проблема | Почему оставлено | Приоритет |
|---|----------|-----------------|-----------|
| 1 | React через CDN + Babel Standalone | Быстрый запуск без инфраструктуры сборки | 🔴 Критический |
| 2 | Нет роутинга (один HTML-файл) | Монолитная структура для прототипа | 🟡 Средний |
| 3 | Нет тестов (unit/integration) | Скорость демонстрации | 🔴 Критический |
| 4 | Нет TypeScript | Ускорение прототипирования | 🟡 Средний |
| 5 | Локальный NLP-парсер на RegExp | AI-backend ещё не развёрнут | 🟢 Низкий |
| 6 | Состояние в памяти, нет persistence | Демо-режим | 🔴 Критический |
| 7 | Нет виртуализации списка задач | При >100 задач тормозит | 🟢 Низкий |
| 8 | Нет drag-and-drop для задач на диаграмме | Не входило в MVP | 🟢 Низкий |
| 9 | Не обрабатывается resize окна | Демо для десктопа | 🟡 Средний |

#### План закрытия

1. **Переезд на Vite + React SPA**
   - `npm create vite@latest` → TypeScript + React
   - Разбить монолитный HTML на компоненты: `GanttChart.tsx`, `ChatPanel.tsx`, `TaskModal.tsx`, `App.tsx`
   - Настроить ESLint + Prettier
   - Оценка: 3–5 дней

2. **Добавить роутинг (React Router)**
   - `/` — список проектов
   - `/project/:id` — диаграмма Гантта
   - Оценка: 1–2 дня

3. **Покрыть тестами**
   - `computeSchedule` — unit-тесты на все типы зависимостей, циклические связи
   - `computeCriticalPath` — тесты на граничные случаи
   - `aiProcessCommand` — тесты на все NLP-команды
   - Компоненты — smoke-тесты через React Testing Library
   - Оценка: 3–5 дней

4. **TypeScript**
   - Добавить типы: `Task`, `Dependency`, `Project`, `ChatMessage`
   - Прописать интерфейсы для всех компонентов
   - Оценка: 2–3 дня (параллельно с п.1)

5. **Локальный NLP-парсер → LLM**
   - Уже реализован fallback: если бэкенд доступен → LLM через MCP, если нет → RegExp
   - После развёртывания бэкенда NLP-парсер остаётся как fallback
   - Оценка: не требуется (уже сделано)

6. **Persistence (сохранение состояния)**
   - `localStorage` → для хранения между сессиями (быстро)
   - PostgreSQL → полноценная БД (см. раздел «Бэкенд»)
   - Оценка: 2–3 дня (localStorage) + 3–5 дней (PostgreSQL)

### 2. Бэкенд

| # | Проблема | Приоритет |
|---|----------|-----------|
| 1 | Нет аутентификации/авторизации | 🔴 Критический |
| 2 | Нет базы данных (in-memory состояние) | 🔴 Критический |
| 3 | Нет rate-limiting | 🟡 Средний |
| 4 | Нет логирования и мониторинга | 🟡 Средний |
| 5 | MCP-сервер не масштабируется | 🟡 Средний |
| 6 | Нет WebSocket (polling для real-time) | 🟢 Низкий |
| 7 | Нет CORS-настроек для production | 🟡 Средний |

#### План закрытия

1. **Аутентификация**
   - OAuth2 (Google, GitHub) через FastAPI middleware
   - JWT-токены
   - Ролевая модель: owner → editor → viewer
   - Оценка: 3–5 дней

2. **База данных**
   - PostgreSQL + SQLAlchemy (async)
   - Миграции через Alembic
   - Модели: `projects`, `tasks`, `dependencies`, `users`, `project_members`
   - Оценка: 5–7 дней

3. **Rate-limiting + безопасность**
   - `slowapi` для rate-limiting
   - CORS для конкретных доменов
   - Валидация входных данных через Pydantic
   - Оценка: 1–2 дня

4. **Мониторинг**
   - Prometheus + Grafana для метрик
   - Sentry для ошибок
   - Структурированные логи (JSON)
   - Оценка: 2–3 дня

### 3. Мульти-проектность и листы

#### Текущее состояние
Фронтенд уже поддерживает несколько проектов через вкладки (sheet tabs), аналогичные листам Excel. Каждый проект — это изолированный набор задач и зависимостей со своей датой старта.

#### Что нужно доработать

| # | Задача | Приоритет |
|---|--------|-----------|
| 1 | **Создание отдельных листов под новые проекты** — кнопка «+» уже есть, но новый проект создаётся пустым. Нужно: при создании проекта сразу открывать импорт Excel или шаблон с засидированными данными | 🟡 Средний |
| 2 | **Копирование задач между проектами** — drag-and-drop задачи на вкладку другого проекта | 🟢 Низкий |
| 3 | **Мастер-проект (агрегация)** — сводная диаграмма по всем проектам, общий критический путь | 🟡 Средний |
| 4 | **Шаблоны проектов** — сохранение структуры проекта как шаблона для повторного использования | 🟢 Низкий |
| 5 | **Экспорт всех листов** — экспорт в Excel с несколькими листами (один лист = один проект) | 🟡 Средний |

### 4. Инфраструктура

| # | Проблема | Приоритет | Решение |
|---|----------|-----------|---------|
| 1 | Нет CI/CD | 🔴 Критический | GitHub Actions → деплой на Vercel (фронт) + Render/Fly.io (бэк) |
| 2 | Нет Docker-образов | 🟡 Средний | Dockerfile для бэкенда, nginx для статики |
| 3 | Нет HTTPS | 🔴 Критический | Автоматически через Vercel/Render |
| 4 | Нет домена | 🟢 Низкий | Купить домен, настроить DNS |
| 5 | Нет резервного копирования | 🟡 Средний | pg_dump cron + S3 |

### 5. Риски

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| LLM API недоступен (OpenAI down) | Средняя | Высокое | Локальный NLP-fallback уже реализован |
| Циклические зависимости «роняют» планировщик | Низкая | Высокое | Защита от циклов реализована, нужны дополнительные тесты |
| Деградация при >500 задач | Средняя | Среднее | Виртуализация (react-window), пагинация |
| Утечка API-ключей LLM | Низкая | Критическое | Все ключи только на бэкенде, rate-limiting на пользователя |
| Пользователь вводит зловредный Excel | Средняя | Среднее | Валидация на бэкенде, ограничение размера файла |

## Порядок закрытия (приоритизированный)

### Фаза 1: Продакшен-ready (2–4 недели)
1. Контейнеризация (Docker) + CI/CD
2. База данных (PostgreSQL + миграции)
3. Аутентификация (OAuth2 + JWT)
4. Переезд фронтенда на Vite + TypeScript
5. HTTPS + домен

### Фаза 2: Стабильность (2–3 недели)
6. Unit + интеграционные тесты
7. Мониторинг (Prometheus, Sentry)
8. Rate-limiting
9. CORS для production

### Фаза 3: Масштабирование и фичи (3–4 недели)
10. **Отдельные листы под проекты с шаблонами** — полноценный механизм создания листов с выбором шаблона или импортом Excel
11. WebSocket для real-time коллаборации
12. Мастер-проект (кросс-проектная агрегация)
13. Виртуализация для больших проектов
14. Drag-and-drop задач на диаграмме
